# federation-grants

Last updated: 2026-10-03

## Responsibility

Session-independent delegated access to an upstream API (#593). A *federation grant* is one user's recorded consent that one confidential client may obtain upstream access tokens through one connection, within stated scopes, until a stated time — and it survives logout. This directory owns the record and its lifecycle, the two store ports, the in-process adapters with their bundled modules, and the domain rules: lifetime (D3), connection revisions (D4), token eligibility (D5), lodging an intent (D6), effective status (D1, D13), retrieval with a coordinated refresh (D10–D12), revocation and listing (D13), the wiring a deployment must have before a grant may outlive a session, audit metadata (D18), and the operator settings.

The design record is the ADR [2026-09-17-federation-grants-offline-delegation.md](../../docs/adr/2026-09-17-federation-grants-offline-delegation.md); every rule here cites its D-number, and this README does not restate the reasons. Not here: the HTTP routes and the consent page (`packages/federation-grants`), the upstream calls (a federation adapter package implementing `SupportsDelegatedAuthorization`, reached through the structural `FederationGrantRefresher`), the Redis adapters (`packages/redis`), and the session-bound token path ([`../federation-tokens/`](../README.md#federation-tokens)), which logout deletes and this directory never touches. That lifetime is why this is its own directory: a grant survives logout and a session-bound token does not, so the two share only the refresh-error classifier and the outage test it reads. "Grant" here is never an OAuth grant type ([`../grants/`](../grants/README.md)), which is why every export says `FederationGrant`.

State ownership: `FederationGrantStore` holds the record, the sealed credential, the refresh lock and the rotation budget; `FederationGrantIntentStore` holds what an acquisition remembers (the intent, the consent challenge, the connect transaction, the per-`(client, subject)` bound); the subject boundary lives in [`../user-sessions/`](../user-sessions/README.md). No operation spans both ports; core orders the two writes once, in `lodge.mts`.

## Public contract

- The record types (the `FederationGrant` union, its connection, effective status, denial and token result) are in [`types.mts`](./types.mts).
- The two ports, with their `ComponentMap` slots, are [`store.mts`](./store.mts) (`federationGrantStore`) and [`intentStore.mts`](./intentStore.mts) (`federationGrantIntentStore`, with the acquisition budget and the per-`(client, subject)` bound).
- The operations a package calls live in [`lodge.mts`](./lodge.mts) (lodging an intent or a reauthorization), [`retrieve.mts`](./retrieve.mts) (`retrieveFederationGrantToken`), [`revoke.mts`](./revoke.mts) (revocation and listing) and the wiring rule `requireFederationGrantSubjectRevocation` ([`revocationWiring.mts`](./revocationWiring.mts)). The structural refresher and the audit-event shape a caller supplies are declared in `retrieve.mts`.
- The bundled memory modules are in [`module.mts`](./module.mts).
- All of it is exported from the root barrel, `FederationGrant` in every name — [`../__tests__/index.barrel.test.mts`](../__tests__/index.barrel.test.mts).

## Inputs and outputs

- Time is the caller's for every record operation: each takes the caller's instant (`now`, or `at` for `revoke` and `touch`), sampled at the write, and what the caller is told is judged on it; what an adapter reclaims is judged on its own clock; no call deletes anything because of a caller's time; a non-date is refused with a `RangeError`, never compared; a non-finite number the record would keep, or a `version` that is not a whole one, refuses the write it arrives in (a bound that is only compared, such as `rowMs`, is compared as given). What an adapter's clock has reclaimed is gone for every caller: a credential past its expiry on that clock is not written back by a refresh whose `now` is still before it. A record's tombstone retention is fixed at its creation and kept with it. The refresh lock is the exception: `acquireRefreshLock` takes `ttlMs` and `waitForMs`, measures its own wait on a monotonic clock, and reports `waitedMs`, which is where the lease's deadlines count from.
- Every transition is a guarded write inside the store; a write that fails says only that it failed, and the caller re-reads and re-evaluates rather than acting on a reason.
- `expired` is never stored; status is computed on every read by `effectiveFederationGrantStatus`, so reverting a configuration change or restoring a key restores the grant.
- Intent handles and credentials never appear on a `FederationGrant`; reads return copies; a `FederationGrantConnection` is built by the package from configuration, with the issuer exactly as configured.
- A client record handed to an exported entry point — lodging takes one from its caller — has its registration fields read through `federationGrantAllowlist`: anything but an array is an empty list. A record read through the `clientRepository` slot is already the client-record boundary's validated copy.
- A retrieval answers one typed `FederationGrantTokenResult`; the HTTP mapping is the package's. An upstream refresh answer is untrusted field by field, and the rotated refresh token is kept whatever else is wrong. No secret enters a denial or an audit event, and the upstream subject an event carries — the IdP's `sub` — is sanitised and capped (`auditErrorText`) where the metadata is built, [`auditMetadata.mts`](./auditMetadata.mts), so every emitter and a composer's own `audit` seam receive it bounded.

## Invariants

- Store contract — [`store.contract.mts`](./__tests__/store.contract.mts), run against memory in [`store.memory.test.mts`](./__tests__/store.memory.test.mts) and against Redis from a copy that `packages/redis/__tests__/federation-grant-contract-parity.test.mts` holds in step: `createPending` refuses a taken ID whatever its state; `activate` takes only the current intent, once, within the lifetime ceiling, with consent not after `now`, never re-pointing a grant, and a refusal changes nothing; `replaceCredentials` / `requireReauthorization` are version-guarded and replace as a whole; `revoke` always wins, in any state, idempotently, and deletes the credential (checked from outside the port); `noteRefreshFailure` counts in the store, in whole milliseconds, and never moves back; `takeRotation`, an optional member, takes one upstream refresh-token rotation from the grant's rotation budget in one atomic step on an `active` grant at the caller's `version` before its expiry — the usage field `rotations` (`{ since, count }`): a new window from `since + windowMs` on, `count + 1` below `limit`, else refused; a `now` behind `since` counts into the window; a `limit` that is not a whole number of at least one or a `windowMs` that is not positive and finite is a `RangeError` — never bumps `version`, takes at once are each counted, `replaceCredentials` keeps it and `activate` resets it, and its cases skip a store without the member; `touch` never moves back and bumps nothing; a version that is not a whole number, and a lifetime, maximum or backoff that is not finite, are refused wherever they arrive; a credential the store's own clock has reclaimed is not replaced; conflicting writes run concurrently end with the grant revoked and no credential behind, and exactly one of two refreshes, callbacks or lodgings wins; the lock excludes, reports `waitedMs`, never acquires after `waitForMs`, has no renewal, releases idempotently and refuses NaN. The memory adapter's own clock rules — reclaiming on its clock, the lock's wait measured on a monotonic one — are in [`store.memory.test.mts`](./__tests__/store.memory.test.mts).
- Intent-store contract — [`intentStore.contract.mts`](./__tests__/intentStore.contract.mts), memory in [`intentStore.memory.test.mts`](./__tests__/intentStore.memory.test.mts), a Redis copy with its own parity test: `putIntent` reserves against the bound atomically and is idempotent for the same record; a reauthorization is not counted; `answerConsent` answers once; `consumeTransaction` hands over once and only for its connection; `finishIntent` releases capacity once; an intent comes back whole, `resource` and `upstreamSubject` included, from a read and in the transaction's snapshot. Both are required keys, `undefined` where there is none, so a store's copy that forgets one fails to compile (#626) — [`intent-fields.types.test.mts`](./__tests__/intent-fields.types.test.mts) (typecheck-included).
- The union refuses, at compile time, a revoked or pending grant with only some authorization fields — [`types.test.mts`](./__tests__/types.test.mts) (typecheck-included).
- Every field of the authorization, the usage, the failure stamp and the credentials is a required key but the access token's `effectiveExpiresAt` and the usage's `rotations` (optional as `takeRotation` is: a store without the member never writes it), `undefined` where there is none, so a store's copy that forgets `resource`, `ineligible`, `refreshFailure` or its `retryAfterSeconds` fails to compile rather than widening the grant or shortening a backoff (#626) — [`record-fields.types.test.mts`](./__tests__/record-fields.types.test.mts) (typecheck-included). The contract reads a cleared field by its value, so a grant never authorized — which has none of those keys — and one whose field was cleared answer alike. The access token's `effectiveExpiresAt` is the one exception, and the types split on it: what a writer hands a store, `FederationGrantCredentialsInput`, must state it as a `Date` — the connect callback and a refresh build it with `federationGrantAccessToken`, and a refresh that keeps the stored token writes the end that token is read to have (`federationGrantKeptAccessToken`, [`held-token.mts`](./held-token.mts)) — so a writer that leaves it out fails to compile. What a store answers, `FederationGrantCredentials`, keeps it optional, and a reader must expect it absent: a record written before the field existed, one rewritten by an earlier release during a rolling deploy, or one whose store could not read it back has none. Such a record ends at `obtainedAt + issuedLifetime`, which serves a token past its adapter's stated end by up to the difference: leaving it out fails open.
- Lifetime: a one-year ceiling, clamp rather than reject, expiry counted from consent — [`lifetime.test.mts`](./__tests__/lifetime.test.mts). Revisions: the persisted format is pinned; identity and authorization change for different reasons — [`revision.test.mts`](./__tests__/revision.test.mts).
- Eligibility, the markers and the failure stamp — [`eligibility.test.mts`](./__tests__/eligibility.test.mts); the reporting order, terminal facts first — [`effective-status.test.mts`](./__tests__/effective-status.test.mts).
- A return URI that already carries a result parameter the end of a flow appends (`grant_id`, `state`, `error`) is refused at registration and at lodging, its names compared as the redirect-URI rule compares the authorization response's: case, `_` and `-` ignored (`GRANT_ID`, `grantId` and `_grant_id` are `grant_id`). The module names its parameters; `net/` owns the comparison — [`lodge.test.mts`](./__tests__/lodge.test.mts).
- Lodging admits the intent before the grant, closes the intent on a refused second write, keeps an ambiguous write that landed, carries what failed on a `storage` refusal, and carries every store error the answer does not stand for on whichever answer follows. A renewal is judged in retrieval's order (D10): a grant that is over, then a removed connection or one the client may no longer use as one refusal, `connection_not_permitted`, then what a renewal cannot mend — [`lodge.test.mts`](./__tests__/lodge.test.mts).
- Retrieval reads the record last, samples time after the reads, refreshes at most once per call, never returns a token from a write that lost, asks the upstream once under the lock, answers at the soft deadline and aborts at the hard one, and remembers a failed refresh. A record answered under an id other than the one asked for, or whose id cannot be read, is the storage outage: nothing of it is served or written, and every write names the id asked for. The version that guards a refresh's writes is read once, before the upstream is asked: one that cannot be read or is not a safe integer is the storage outage, and the upstream is not asked. A refresh answer is read, and its access token judged, by `readFederationGrantUpstreamAnswer` ([`upstream-answer.mts`](./upstream-answer.mts), [`upstream-answer.test.mts`](./__tests__/upstream-answer.test.mts)), the one rule the connect callback reads its code exchange's answer by too. Each field is read once; a read that throws, a field of the wrong type, a missing `token_type` (RFC 6749 §5.1) and a scope that names no scope-token are `malformed_token_response`; a blank scope, like an absent one, means the grant's. The lifetime is read by `readUpstreamTokenLifetime`, and is finite only when both fields state it and life is left when the answer is read; anything else is `no_finite_lifetime`. The stored token keeps when it was obtained (the call's start), the lifetime as issued, which every disclosure judges against the current maximum, and `effectiveExpiresAt`, when it ends; one without `effectiveExpiresAt` ends at `obtainedAt + issuedLifetime`, and none ends later ([`held-token.mts`](./held-token.mts), [`held-token.test.mts`](./__tests__/held-token.test.mts)). A held token's age is `judgeHeldUpstreamToken`'s — [`retrieve.evaluation.test.mts`](./__tests__/retrieve.evaluation.test.mts), [`retrieve.refresh.test.mts`](./__tests__/retrieve.refresh.test.mts), [`retrieve.rotation.test.mts`](./__tests__/retrieve.rotation.test.mts), [`retrieve.fallback.test.mts`](./__tests__/retrieve.fallback.test.mts), [`retrieve.backoff.test.mts`](./__tests__/retrieve.backoff.test.mts), [`retrieve.hostile.test.mts`](./__tests__/retrieve.hostile.test.mts); a `503` carries the very failure it reported, where nothing that spreads or serialises the answer sees it — [`retrieve.failure.test.mts`](./__tests__/retrieve.failure.test.mts).
- `revokeFederationGrant` is idempotent, does not read first, and audits only a transition it made — [`revoke.test.mts`](./__tests__/revoke.test.mts); the wiring refusals — [`revocationWiring.test.mts`](./__tests__/revocationWiring.test.mts); the settings equal `reference.conf` value for value and refuse rather than default over an invalid value — [`settings.test.mts`](./__tests__/settings.test.mts); [`allowlist.test.mts`](./__tests__/allowlist.test.mts), [`auditMetadata.test.mts`](./__tests__/auditMetadata.test.mts), [`module.test.mts`](./__tests__/module.test.mts).

## Failure and lifecycle

- Refusal is a typed denial (`FederationGrantDenial`: `grant_revoked`, `reauthorization_required`, …); failure is `temporarily_unavailable` with a reason (`upstream`, `storage`, `lock_timeout`, `concurrent_update`, `key_unavailable`). Nothing is destroyed because it could not be read (D16); a boundary that cannot be read is an outage answered 503, never a status — after the record alone has been judged: a stored revocation or a pending grant is answered from the record first, by retrieval and a renewal alike.
- What failed goes to the package that answers, never into a response: a retrieval tells its `report` seam every failure it turns into an answer or drops — a retried write once per distinct kind of failure (name and code), with the last error of that kind and `attempts`; a write, a mark or an upstream call that did not answer in time as not answered — and a `temporarily_unavailable` turned from one carries that same object as `failure`. A lodging's `storage` refusal carries its store, step, error or refusal as `failure`; any lodging answer, a success included, carries the store errors it does not stand for as `absorbed` (a write that threw and landed, a question that could not be asked, a pointer write whose re-read decided, an intent it could not close); a `connection_not_configured` refusal carries its `connection`. All are attached by [`carry.mts`](./carry.mts), not enumerable, so the route logs the outage once and the rest as what the answer did not carry.
- Whether a failed upstream call is an outage or the upstream's refusal is `isFederationUpstreamOutage` ([`../federation-tokens/upstreamOutage.mts`](../federation-tokens/upstreamOutage.mts), beside the refresh-error classifier, which reads it first), for the connect callback's exchange and the retrieval's refresh: an abort or timeout, a connection code, or a 5xx status, on the error or its causes that are Errors, or on a `Response` it was raised over, including an Error or `Response` a thrown non-Error carries as its `cause` — never its text, and never a peer's parsed body. The retrieval also takes as an outage what the classifier reads structurally as `network` on a thrown value that is not an Error — a 5xx status or a connection code on the value itself, which a hand-written adapter may throw — and nothing from a cause that is neither an Error nor a Response. So the classifier's `invalid_grant`, on which the retrieval requires reauthorization, is never an outage, and never a message's text — [`../federation-tokens/__tests__/upstreamOutage.test.mts`](../federation-tokens/__tests__/upstreamOutage.test.mts), [`retrieve.failure.test.mts`](./__tests__/retrieve.failure.test.mts), and against the real openid-client in federation-oidc's `delegated-outage.test.mts`.
- Deadlines: a retrieval has a soft deadline (the caller is answered; the late result is still persisted) and a hard one (the upstream call is aborted, the lock released); every deadline counts from when the store took the lock. An acquisition has one deadline, the intent's, ten minutes from lodging.
- Boot-time refusals: `requireFederationGrantSubjectRevocation` refuses no boundary at all, a single-boundary adapter, and durable grants beside an in-memory boundary; both memory modules are refused under `core.deployment.mode = "multi"`.
- Cleanup: the memory adapters sweep amortized on writes and hold no standing timers — the lock wait polls with a bounded `setTimeout` that never outlives the call; a retrieval leaves no timer once answered and its late work done. Nothing to dispose.
