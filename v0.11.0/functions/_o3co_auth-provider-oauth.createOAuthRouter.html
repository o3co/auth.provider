        • OptionalsubjectRevocation?: SubjectRevocation

          #296 — per-subject access-token watermark. The subject-level companion to accessTokenDenylist: the denylist revokes a token the client named, this revokes every token a subject held as of a credential change, which cannot be expressed as a set of jtis. Forwarded to every surface that already consults the denylist, so a watermark written by revokeAllForSubject is honoured rather than inert.
