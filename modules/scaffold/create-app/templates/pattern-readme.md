## Start

1. `pnpm install`
2. Copy `.env.example` to `.env`, uncomment each line and replace its placeholder.
3. Copy `{{localExample}}` to `{{local}}`, uncomment each key and replace its placeholders, and add the keys this guide names that neither file holds.
4. `APP_CONFIG={{local}},{{application}} pnpm start`

Both examples hold every value in a comment: a copy left as it is sets nothing, and boot refuses each key still needed.
A secret's placeholder begins `REPLACE-`; uncommented as it is, boot refuses it. Delete the line of an optional key left unset.

Until every key the modules need is written, the app writes each refusal on standard error, one per line, and exits 78.
SIGTERM or SIGINT stops it, draining what is under way, within `kernel.stop-seconds` (30 by default); give an orchestrator a grace period longer than `kernel.stop-seconds`.

## Docker

1. `docker build -t auth-provider .`
2. `docker run --env-file .env -e APP_CONFIG={{local}},{{application}} -v "$PWD/{{local}}:/app/{{local}}:ro" -p {{port}}:{{port}} auth-provider`

Docker reads one line per variable from an env file: write a value of several lines, such as a PEM key, in the local layer instead.
The image runs as a user other than root and installs the locked production dependencies only. `tini` runs as process 1, so `docker stop` reaches the app and it stops cleanly.
Its health check asks `/_healthcheck`, which answers while the process runs; `/readyz` answers readiness, for a load balancer.

## Changing the pattern

Generate again and carry the configuration over:

- `create-app <target> --pattern {{name}} --add <feature>` adds a feature, with what it needs, its wirings and bridges.
- `--axis <owner>=<adapter>` chooses an axis's adapter, or the owner itself.
- `--login`, `--second-factor`, `--grants`, `--client-auth` and `--binding` each replace that group of features with the comma-separated list given.

Boot names what a change needs, and what cannot be composed.
