# rp-logout-store

Wires `rp-logout`'s store interfaces to `records`: the clients of each session to keyed sets on `kernel`'s clock, and the notices not yet delivered to deferred work. Each has its own space, which declares a guarantee for each need `rp-logout` states. The operator section sets `clients-per-session` (1–1000, default 64), the cap of each session's set; a session's clients are those that redeemed a code in it, few in practice, and one pushed out over the cap is answered, so `rp-logout` logs it. The notices are spread over `notice-shards` shards (1–65536, default 64) of up to `notices-per-shard` notices (1–10000, default 1000), and an add to a full shard is refused rather than push one out; a notice stays only while its client cannot be reached, so the defaults, about 64,000, leave room for an outage of some clients. A need with nothing mapped to it fails the type check, and `rp-logout`'s store contract, run on a store that loses what a missing guarantee allows, checks what each guarantee means. The wiring only maps, with no branches or loops. Depends on `kernel`, `rp-logout`, `records` and `store`.
