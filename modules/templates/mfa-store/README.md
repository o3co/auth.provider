# mfa-store

Wires `mfa`'s store interface, factor lists and the claims on unique values, to `subject-records`' records, kept without end over the phase this process reads once: its one space, `mfa-store.factors`, is declared `online-indexed` and erased by `mfa`, beside its index space, and a list and a claim are changed as one through `subject-records`' joint change (`updateAsOne`; a store that cannot write records of two partitions as one refuses the boot, as `subject-records` tells it). The space declares a guarantee for each need `mfa` states, and `subject-records`' `tombstoneFloor` beside them, as its index holds the subject's tombstone with the same guarantees. Every port comes straight from the builders, `erase` and `migrate` among them. The composition is out of traffic while the phase cannot be read (probe `mfa-store.phase`). A need with nothing mapped to it fails the type check, and `mfa`'s store contract, run on a store that loses what a missing guarantee allows, in both phases, checks what each guarantee means. The wiring only maps, with no branches or loops. Depends on `kernel`, `mfa`, `subject-records` and `store`.
