# refresh-store

Wires `refresh`'s store interfaces to `records`: families, what each redemption left and the family of each access token to records, the families of each session and the access tokens of each family to keyed sets on `kernel`'s clock, and the families to settle to deferred work. Each has its own space, which declares a guarantee for each need `refresh` states, so names from different interfaces never meet. The operator section sets `families-per-session` and `tokens-per-family` (1–10000, default 1000), the caps of the keyed sets; each set is one record rewritten whole, so its cap stays small, and 1,000 is more than a client should need within one access token's lifetime. Past a cap, `refresh` revokes what is pushed out. The families to settle are spread over `settle-shards` shards (1–65536, default 1024) of up to `settles-per-shard` families (1–10000, default 1000); a family stays listed only while revoking its tokens keeps failing, so the defaults, about a million, leave room for a long outage while one shard stays near 50 KB. A need with nothing mapped to it fails the type check, and `refresh`'s store contract, run on a store that loses what a missing guarantee allows, checks what each guarantee means. The wiring only maps, with no branches or loops. Depends on `kernel`, `refresh`, `records` and `store`.
