# refresh-store

Wires `refresh`'s store interfaces to `records`: families, what each redemption left and the family of each access token to records, the families of each session and the access tokens of each family to keyed sets on `kernel`'s clock, and the families to settle to deferred work. Each has its own space, which declares a guarantee for each need `refresh` states, so names from different interfaces never meet. The sets of each session and of each family, and the families to settle, are deprecated: `refresh` neither reads nor writes them, so they are still wired, unused, and the operator section's `families-per-session`, `tokens-per-family` (1–10000, default 1000), `settle-shards` (1–65536, default 1024) and `settles-per-shard` (1–10000, default 1000) are taken with no effect; a later release removes the sets and refuses the keys. A need with nothing mapped to it fails the type check, and `refresh`'s store contract, run on a store that loses what a missing guarantee allows, checks what each guarantee means. The wiring only maps, with no branches or loops. Depends on `kernel`, `refresh`, `records` and `store`.
