# session-tokens-store

Wires `session-tokens`' store interfaces to `records`: the tokens issued in each session to keyed sets on `kernel`'s clock, the token index to records, and the sessions pending a push-out to deferred work. Each has its own space, which declares a guarantee for each need `session-tokens` states. The operator section sets `references-per-session` (1–10000, default 1000), the cap of each session's set: past it, the set answers the reference that ends first as pushed out, keeping it awaiting in the same write, and `session-tokens` revokes its token. The index keeps one record per token id with no cap, ended by the store after its lifetime, and names it by the token id as it is, as `session-tokens` states no names from secrets. The pending sessions are spread over `pending-shards` shards (1–65536, default 64) of up to `pending-per-shard` sessions (1–10000, default 1000), and refuse when a shard is full rather than push one out; a session is listed when an add comes near its cap, and leaves once what it pushed out is revoked, so the defaults, about 64,000, leave room for an outage of revocation. A need with nothing mapped to it fails the type check, and `session-tokens`' store contract, run on a store that loses what a missing guarantee allows, checks what each guarantee means. The wiring only maps, with no branches or loops. Depends on `kernel`, `session-tokens`, `records` and `store`.
