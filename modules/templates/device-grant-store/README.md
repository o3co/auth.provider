# device-grant-store

Wires `device-grant`'s store interfaces. Devices go to `records` under a secret, by the name `records` makes from a device code, so a device code never reaches the store; their walk, for erasure, is records' own. User codes go to records. Approvals go to `subject-records` over the phase this process reads once, in `device-grant-store.approvals`: keyed by the device's name (a digest), `bounded` by `device-grant`'s `approvalRecordMaxMs`, fenced at creation by the subject's tombstone, erased by `device-grant`, beside its index space, declaring `tombstoneFloor`, every port the builder's own. The composition is out of traffic while the phase cannot be read (probe `device-grant-store.phase`). Each has its own space, so a device's name and a user code never meet, and each declares a guarantee for each need `device-grant` states. A need with nothing mapped to it, a guarantee or records under a secret, fails the type check, and `device-grant`'s store contract, run in both phases on a store that loses what a missing guarantee allows, checks what each guarantee means. The wiring only maps, with no branches or loops. The user codes' space holds no subject's data (`subjectData: none`): a code a person types, chosen at random, and the name of the device it leads to, a digest. Depends on `kernel`, `device-grant`, `records`, `subject-records` and `store`.
