# claims-selection-store

Wires `claims-selection`'s store interface. Selections go to `subject-records` over the phase this process reads once, in `claims-selection-store.selections`: `online-indexed`, each record created for its subject, fenced at creation by the subject's tombstone, erased by `claims-selection`, beside its index space, declaring `tombstoneFloor`, every port the builder's own (`create`, `read`, `erase`, `migrate`; never a raw `save` on an indexed space). The composition is out of traffic while the phase cannot be read (probe `claims-selection-store.phase`). The space declares a guarantee for each need `claims-selection` states. A need with nothing mapped to it fails the type check, and `claims-selection`'s store contract, run in both phases on a store that loses what a missing guarantee allows, checks what each guarantee means. The wiring only maps, with no branches or loops. Depends on `kernel`, `claims-selection`, `subject-records` and `store`.
