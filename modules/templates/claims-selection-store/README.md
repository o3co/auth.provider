# claims-selection-store

Wires `claims-selection`'s store interface to `records`: selections as records in a space of their own, which declares a guarantee for each need `claims-selection` states. A need with nothing mapped to it fails the type check, and `claims-selection`'s store contract, run on a store that loses what a missing guarantee allows, checks what each guarantee means. The wiring only maps, with no branches or loops. Depends on `kernel`, `claims-selection`, `records` and `store`.

The constrained families' list is `records`' deferred work in a space of its own, with the same guarantees, spread over `constrained-shards` shards of at most `constrained-per-shard` families. Size it at about the rate constrained families start times the family lifetime, doubled for shards filling unevenly. Past a full shard a constrained family does not start (`records.full`); others are unaffected. To recover, raise `constrained-per-shard`; never change `constrained-shards` while the list holds any, as the list would lose what it holds.
