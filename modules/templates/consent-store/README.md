# consent-store

Wires `consent`'s store interfaces to `subject-records`: grants in a space declaring `online-indexed`, and asks under a secret in one declaring `bounded` by consent's ask bound (`askLifetimeMaxMs`), so an ask's key never reaches the store; each with its index space, both erased by `consent`. Each space declares a guarantee for each need `consent` states for it; a need with nothing mapped to it fails the type check, and `consent`'s store contracts, run in both phases on a store that loses what a missing guarantee allows, check what each guarantee means. Every port is the phased builder's own (`save` its `create`, the subject last; `erase` and `migrate` at the phase read), mapped with no arrow, so the wiring never handles the phase. The phase is read once from the store's control, if any (`reader` without one); a store's blip at start refuses no start, the probe `consent-store.phase` keeping the node out of traffic until it reads. The wiring only maps, with no branches or loops. Depends on `kernel`, `consent`, `store` and `subject-records`.
