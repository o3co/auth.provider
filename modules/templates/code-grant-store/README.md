# code-grant-store

Wires `code-grant`'s store interfaces to `records`: codes to records under a secret, by the name `records` makes from a code, so a code never reaches the store, and the codes to revoke to deferred work. Each has its own space, which declares a guarantee for each need `code-grant` states. The codes to revoke are spread over `void-shards` shards (1–65536, default 1024) of up to `voids-per-shard` codes (1–10000, default 1000); a code is listed only when it comes again or its redemption is cut short, so the list grows no faster than codes are issued, and the defaults, about a million, leave room for a long outage of revocation while one shard stays near 50 KB. A need with nothing mapped to it, a guarantee or records under a secret, fails the type check, and `code-grant`'s store contract, run on a store that loses what a missing guarantee allows, checks what each guarantee means. The wiring only maps, with no branches or loops. Depends on `kernel`, `code-grant`, `records` and `store`.
