# federation-grants-store

Wires `federation-grants`' store interfaces to `records`, each in its own space that declares a guarantee for each need `federation-grants` states. Grants go to keyed records; the steps a browser takes go to records under a secret, so no link, question or upstream state reaches the store; refresh locks, under a holder's mark and changed only from the mark held, go to keyed records created only where none is held. The first-time intents waiting per client and subject, and each subject's grants, go to keyed sets on `kernel`'s clock. The operator section sets their caps: `pending-per-client-and-subject` (1–1000, default 16, more than one client should leave waiting for one user), past which the intent ending first is pushed out and `federation-grants` ends it; and `grants-per-subject` (1–10000, default 100, far above what one user holds), past which the grant ending first is pushed out and logged, skipping only a revocation's closing work. A need with nothing mapped to it fails the type check, and `federation-grants`' store contracts, run here on a simulated store through a restart, memory pressure, a failover and an unconfirmed read, checks what each guarantee means. The wiring only maps, with no branches or loops. Depends on `kernel`, `federation-grants`, `records` and `store`.
