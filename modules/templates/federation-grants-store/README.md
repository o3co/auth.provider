# federation-grants-store

Wires `federation-grants`' store interfaces, each in its own space that declares a guarantee for each need `federation-grants` states. Grants, the pending intents and each subject's grants are a subject's data, on `subject-records` over the phase this process reads once, each beside its index space, erased by `federation-grants` and declaring `tombstoneFloor` (the pending intents gain durable and replicated by it): grants as records (`online-indexed`), the pending intents by client and subject as keyed sets (`online-indexed`), each subject's grants as keyed sets keyed by the subject (`online-keyed`), the sets on `kernel`'s clock; every port the builders' own, `erase` and `migrate` among them. The composition is out of traffic while the phase cannot be read (probe `federation-grants-store.phase`). The steps a browser takes go to `records` under a secret, so no link, question or upstream state reaches the store; refresh locks, under a holder's mark and changed only from the mark held, go to keyed records created only where none is held. The operator section sets their caps: `pending-per-client-and-subject` (1–1000, default 16, more than one client should leave waiting for one user), past which the intent ending first is pushed out and `federation-grants` ends it; and `grants-per-subject` (1–10000, default 100, far above what one user holds), past which the grant ending first is pushed out and logged, skipping only a revocation's closing work. A need with nothing mapped to it fails the type check, and `federation-grants`' store contracts, run here on a simulated store in both phases through a restart, memory pressure, a failover and an unconfirmed read, checks what each guarantee means. The wiring only maps, with no branches or loops. The steps' and the locks' spaces hold no subject's data (`subjectData: none`): random link and question handles with the grant, intent and session they lead to, and grant ids with a lock's mark. Depends on `kernel`, `federation-grants`, `records`, `subject-records` and `store`.
