# federation-tokens-store

Wires `federation-tokens`' store interfaces. Each session's upstream tokens are one keyed record of `subject-records` over the phase this process reads once, in `federation-tokens-store.tokens` (`online-indexed`, erased by `federation-tokens`, beside its index space; every port the builder's own, `erase` and `migrate` among them), a space declaring a guarantee for each need `federation-tokens` states for them (no eviction, not rolled back by failover) and `tombstoneFloor`, durable among it. The composition is out of traffic while the phase cannot be read (probe `federation-tokens-store.phase`). Refresh locks are `records`' keyed records, holding their holder's mark, created only where none is held, for the lock's lifetime, and changed only over the version a change read, in a space declaring no eviction. A need with nothing mapped to it fails the type check, and `federation-tokens`' store contract, run on a store that loses what a missing guarantee allows, checks what each guarantee means, in both phases. The wiring only maps, with no branches or loops. The locks' space holds no subject's data (`subjectData: none`): a session's handle and an identity provider's name, with a lock's mark. Depends on `kernel`, `federation-tokens`, `records`, `subject-records` and `store`.
