# RFC 8414: OAuth 2.0 Authorization Server Metadata

## 2 Authorization Server Metadata

- **rfc8414-2-a** MUST: the metadata holds `issuer`, an https URL with no query and no fragment.
  note: N-https
- **rfc8414-2-b** MUST: the metadata holds `authorization_endpoint` where a grant that uses it is offered.
- **rfc8414-2-c** MUST: the metadata holds `token_endpoint` where a grant other than the implicit one is offered.
- **rfc8414-2-d** MUST: the metadata's `jwks_uri` uses the https scheme.
  note: N-https
- **rfc8414-2-e** MUST: where the key set holds both signing and encryption keys, every key has `use`.
  out-of-scope: the key set holds signing keys alone; no encryption key is published.
- **rfc8414-2-f** SHOULD: the metadata holds `scopes_supported`.
- **rfc8414-2-g** MUST: the metadata holds `response_types_supported`.
  note: N-response-types
- **rfc8414-2-h** MUST: where `token_endpoint_auth_methods_supported` lists `private_key_jwt` or `client_secret_jwt`, `token_endpoint_auth_signing_alg_values_supported` is present.
- **rfc8414-2-i** SHOULD: the token endpoint takes `RS256` for a client's assertion.
- **rfc8414-2-j** MUST NOT: `token_endpoint_auth_signing_alg_values_supported` lists `none`.
- **rfc8414-2-k** SHOULD: a client registration process shows `op_policy_uri`, where given, to the person registering.
  out-of-scope: there is no client registration process; the operator writes the clients.
- **rfc8414-2-l** MUST: where `revocation_endpoint_auth_methods_supported` lists `private_key_jwt` or `client_secret_jwt`, `revocation_endpoint_auth_signing_alg_values_supported` is present.
- **rfc8414-2-m** MUST NOT: `revocation_endpoint_auth_signing_alg_values_supported` lists `none`.
- **rfc8414-2-n** MUST: where `introspection_endpoint_auth_methods_supported` lists `private_key_jwt` or `client_secret_jwt`, `introspection_endpoint_auth_signing_alg_values_supported` is present.
- **rfc8414-2-o** MUST NOT: `introspection_endpoint_auth_signing_alg_values_supported` lists `none`.
- **rfc8414-2-p** SHOULD: a client registration process shows `op_tos_uri`, where given, to the person registering.
  out-of-scope: there is no client registration process; the operator writes the clients.

## 2.1 Signed Authorization Server Metadata

- **rfc8414-2.1-a** MUST: `signed_metadata` is signed or MACed with JWS.
  out-of-scope: no `signed_metadata` is published.
- **rfc8414-2.1-b** SHOULD NOT: `signed_metadata` appears as a claim inside the signed metadata.
  out-of-scope: no `signed_metadata` is published.
- **rfc8414-2.1-c** MUST: `signed_metadata` carries an `iss` claim naming the party attesting to it.
  out-of-scope: no `signed_metadata` is published.

## 3 Obtaining Authorization Server Metadata

- **rfc8414-3-a** MUST: the metadata is served at the path made by inserting the well-known string between the issuer identifier's host and its path.
- **rfc8414-3-b** MUST: that path is served over https.
- **rfc8414-3-c** MUST: every well-known suffix the metadata is served under is one registered with IANA.

## 3.1 Authorization Server Metadata Request

- **rfc8414-3.1-a** MUST: the metadata is answered to a `GET` at its path.

## 3.2 Authorization Server Metadata Response

- **rfc8414-3.2-a** MUST: the metadata is answered with `200` and a JSON object of type `application/json`.
- **rfc8414-3.2-b** MUST: a claim with no values is left out of the metadata.

## 3.3 Authorization Server Metadata Validation

- **rfc8414-3.3-a** MUST: the metadata's `issuer` is identical to the issuer identifier the path it is served at was made from.
