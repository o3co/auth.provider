# RFC 6749: The OAuth 2.0 Authorization Framework

## 2.1 Client Types

- **rfc6749-2.1-a** SHOULD NOT: the server assumes a client's type instead of taking the type it was registered with.

## 2.2 Client Identifier

- **rfc6749-2.2-a** MUST NOT: the server takes a client identifier alone as the client's authentication.
- **rfc6749-2.2-b** SHOULD: the server documents the size of the client identifiers it issues.
  out-of-scope: client identifiers are written by the operator, never issued by the server.

## 2.3 Client Authentication

- **rfc6749-2.3-a** MUST NOT: the server relies on a public client's authentication to identify the client.
- **rfc6749-2.3-b** MUST NOT: a request that authenticates the client by more than one method is taken.

## 2.3.1 Client Password

- **rfc6749-2.3.1-a** MUST: a client issued a password can authenticate with the HTTP Basic scheme.
- **rfc6749-2.3.1-b** MUST NOT: client credentials are taken from the request URI.
- **rfc6749-2.3.1-c** MUST: an endpoint that takes a client password is protected against brute force.
- **rfc6749-2.3.1-d** MUST: a client authenticating in the request body sends `client_id`, and `client_secret` unless its secret is the empty string; a client whose secret is not empty does not authenticate without it.

## 2.3.2 Other Authentication Methods

- **rfc6749-2.3.2-a** MUST: each client's registration names the authentication method it is held to.

## 3.1 Authorization Endpoint

- **rfc6749-3.1-a** MUST: the authorization endpoint authenticates the resource owner before it authorizes anything.
- **rfc6749-3.1-b** MUST NOT: the authorization endpoint's URI has a fragment.
- **rfc6749-3.1-c** MUST: the authorization endpoint takes `GET`.
- **rfc6749-3.1-d** MUST: at the authorization endpoint, a parameter sent without a value is read as left out.
- **rfc6749-3.1-e** MUST: the authorization endpoint ignores parameters it does not recognize.
- **rfc6749-3.1-f** MUST NOT: the authorization endpoint takes a request that repeats a parameter, or repeats one in its response.

## 3.1.1 Response Type

- **rfc6749-3.1.1-a** MUST: an authorization request without `response_type`, or with one not understood, is answered with an error response.

## 3.1.2 Redirection Endpoint

- **rfc6749-3.1.2-a** MUST: a registered redirection URI is an absolute URI.
- **rfc6749-3.1.2-b** MUST: the query of a redirection URI is kept when the server adds its parameters to it.
- **rfc6749-3.1.2-c** MUST NOT: a redirection URI with a fragment is registered or redirected to.

## 3.1.2.1 Endpoint Request Confidentiality

- **rfc6749-3.1.2.1-a** SHOULD: before redirecting to a redirection URI without TLS, the server warns the resource owner.

## 3.1.2.2 Registration Requirements

- **rfc6749-3.1.2.2-a** MUST: a public client must register its redirection URIs.
- **rfc6749-3.1.2.2-b** SHOULD: every client must register its redirection URIs before it uses the authorization endpoint.
- **rfc6749-3.1.2.2-c** SHOULD: a client registers its complete redirection URIs.
- **rfc6749-3.1.2.2-d** SHOULD: where a complete redirection URI is not registered, its scheme, authority and path are.

## 3.1.2.3 Dynamic Configuration

- **rfc6749-3.1.2.3-a** MUST: where more than one redirection URI is registered, only part of one, or none, an authorization request without `redirect_uri` is refused; where one complete URI is registered, `redirect_uri` may be left out.
- **rfc6749-3.1.2.3-b** MUST: a `redirect_uri` sent is matched against the registered redirection URIs.
- **rfc6749-3.1.2.3-c** MUST: a `redirect_uri` is compared with a complete registered URI by simple string comparison.

## 3.1.2.4 Invalid Endpoint

- **rfc6749-3.1.2.4-a** SHOULD: a request that fails validation for a missing, invalid or mismatching redirection URI is answered to the resource owner with its error.
- **rfc6749-3.1.2.4-b** MUST NOT: after a request fails validation for a missing, invalid or mismatching redirection URI, the user-agent is redirected to that URI.

## 3.2 Token Endpoint

- **rfc6749-3.2-a** MUST NOT: the token endpoint's URI has a fragment.
- **rfc6749-3.2-b** MUST: at the token endpoint, a parameter sent without a value is read as left out.
- **rfc6749-3.2-c** MUST: the token endpoint ignores parameters it does not recognize.
- **rfc6749-3.2-d** MUST NOT: the token endpoint takes a request that repeats a parameter, or repeats one in its response.

## 3.2.1 Client Authentication

- **rfc6749-3.2.1-a** MUST: a confidential client, or one issued credentials, is authenticated at the token endpoint.
- **rfc6749-3.2.1-b** MUST: a code redeemed by a client that does not authenticate is refused without `client_id`.

## 3.3 Access Token Scope

- **rfc6749-3.3-a** MUST: where the scope issued differs from the one asked, the answer carries `scope`.
- **rfc6749-3.3-b** MUST: a request without `scope` gets a predefined default or fails as an invalid scope.
- **rfc6749-3.3-c** SHOULD: the server documents its scope requirements and default.

## 4.1.2 Authorization Response

- **rfc6749-4.1.2-a** MUST: a granted authorization request is redirected with `code`.
- **rfc6749-4.1.2-b** MUST: an authorization code expires shortly after it is issued.
- **rfc6749-4.1.2-c** SHOULD: an authorization code lives at most ten minutes.
- **rfc6749-4.1.2-d** MUST: a code redeemed a second time is refused.
- **rfc6749-4.1.2-e** SHOULD: a code redeemed a second time revokes the tokens issued from it.
- **rfc6749-4.1.2-f** MUST: the authorization response carries the `state` the request sent, as sent.
- **rfc6749-4.1.2-g** SHOULD: the server documents the size of the codes it issues.

## 4.1.2.1 Error Response

- **rfc6749-4.1.2.1-a** SHOULD: a request that fails for a missing, invalid or mismatching redirection URI, or a missing or invalid client identifier, is answered to the resource owner with its error.
- **rfc6749-4.1.2.1-b** MUST NOT: after a request fails for a missing, invalid or mismatching redirection URI, or a missing or invalid client identifier, the user-agent is redirected to the invalid redirection URI.
- **rfc6749-4.1.2.1-c** MUST: any other failed or denied authorization request is redirected with `error`.
- **rfc6749-4.1.2.1-d** MUST NOT: an `error` value holds a character outside %x20-21 / %x23-5B / %x5D-7E.
- **rfc6749-4.1.2.1-e** MUST NOT: an `error_description` value holds a character outside %x20-21 / %x23-5B / %x5D-7E.
- **rfc6749-4.1.2.1-f** MUST: an `error_uri` value is a URI reference within %x21 / %x23-5B / %x5D-7E.
- **rfc6749-4.1.2.1-g** MUST: the error response carries the `state` the request sent, as sent.

## 4.1.3 Access Token Request

- **rfc6749-4.1.3-a** MUST: redeeming a code requires the authentication of a confidential client, or of one issued credentials.
- **rfc6749-4.1.3-b** MUST: a client's authentication sent with a code is checked.
- **rfc6749-4.1.3-c** MUST: a code is redeemed only by the client it was issued to.
- **rfc6749-4.1.3-d** MUST: a code redeemed is valid.
- **rfc6749-4.1.3-e** MUST: where the authorization request sent `redirect_uri`, the code is redeemed only with the identical `redirect_uri`.

## 4.2.1 Authorization Request

- **rfc6749-4.2.1-a** MUST: an implicit grant redirects its access token only to a redirection URI the client registered.
  out-of-scope: the implicit grant is not offered (`response_types_supported` is `code`).

## 4.2.2 Access Token Response

- **rfc6749-4.2.2-a** MUST: the implicit grant's response carries `access_token`, `token_type`, `scope` where it differs and `state`, and no refresh token.
  out-of-scope: the implicit grant is not offered.
- **rfc6749-4.2.2-b** SHOULD: the implicit grant's response carries `expires_in`, or the lifetime is documented, as is the size of its values.
  out-of-scope: the implicit grant is not offered.

## 4.2.2.1 Error Response

- **rfc6749-4.2.2.1-a** MUST: the implicit grant's errors follow the forms of 4.1.2.1, in the fragment.
  out-of-scope: the implicit grant is not offered.
- **rfc6749-4.2.2.1-b** SHOULD: the implicit grant's errors on the redirection URI are told to the resource owner.
  out-of-scope: the implicit grant is not offered.

## 4.3.2 Access Token Request

- **rfc6749-4.3.2-a** MUST: the password grant requires a confidential client's authentication and checks the resource owner's password.
  out-of-scope: the resource owner password credentials grant is not offered.
- **rfc6749-4.3.2-b** MUST: the password grant's endpoint is protected against brute force.
  out-of-scope: the resource owner password credentials grant is not offered.

## 4.4 Client Credentials Grant

- **rfc6749-4.4-a** MUST: the client credentials grant is refused to a public client.

## 4.4.2 Access Token Request

- **rfc6749-4.4.2-a** MUST: the client credentials grant authenticates the client.

## 4.4.3 Access Token Response

- **rfc6749-4.4.3-a** SHOULD NOT: the client credentials grant's answer includes a refresh token.

## 5.1 Successful Response

- **rfc6749-5.1-a** MUST: a token response carries `access_token` and `token_type`.
- **rfc6749-5.1-b** SHOULD: a token response carries `expires_in`.
- **rfc6749-5.1-c** SHOULD: where a token response has no `expires_in`, the lifetime is told otherwise or documented.
- **rfc6749-5.1-d** MUST: a response holding tokens, credentials or other secrets carries `Cache-Control: no-store` and `Pragma: no-cache`.
- **rfc6749-5.1-e** SHOULD: the server documents the size of the tokens it issues.

## 5.2 Error Response

- **rfc6749-5.2-a** MUST: a token endpoint error is answered `400` with `error`, unless said otherwise.
- **rfc6749-5.2-b** MUST: a client that tried to authenticate with the `Authorization` header and failed is answered `401` with a `WWW-Authenticate` of the scheme it used.
- **rfc6749-5.2-c** MUST NOT: an `error` value holds a character outside %x20-21 / %x23-5B / %x5D-7E.
- **rfc6749-5.2-d** MUST NOT: an `error_description` value holds a character outside %x20-21 / %x23-5B / %x5D-7E.
- **rfc6749-5.2-e** MUST: an `error_uri` value is a URI reference within %x21 / %x23-5B / %x5D-7E.
- **rfc6749-5.2-f** MUST: a token request without `grant_type`, or without a parameter its grant requires (`code`, `refresh_token`), is refused with `invalid_request`; one whose `grant_type` the server does not serve, with `unsupported_grant_type`.

## 6 Refreshing an Access Token

- **rfc6749-6-a** MUST NOT: a refresh request is granted a scope beyond the one first granted.
- **rfc6749-6-b** MUST: a refresh requires the authentication of a confidential client, or of one issued credentials.
- **rfc6749-6-c** MUST: a refresh token is used only by the client it was issued to.
- **rfc6749-6-d** MUST: a refresh token is checked before it is used.
- **rfc6749-6-e** MUST: a new refresh token has the scope of the one it replaces.

## 7 Accessing Protected Resources

- **rfc6749-7-a** MUST: the server, as a protected resource (such as UserInfo), validates the access token, that it has not expired and that its scope covers the resource asked.
  role: rs

## 7.2 Error Response

- **rfc6749-7.2-a** SHOULD: the server, as a protected resource, tells the client the error of a request that fails.
  role: rs

## 8.2 Defining New Endpoint Parameters

- **rfc6749-8.2-a** MUST: a parameter the server adds to an endpoint has a name of param-name characters and a defined syntax for its value.
- **rfc6749-8.2-b** SHOULD: a parameter the server adds without registering it carries a vendor prefix unlikely to clash with registered ones.

## 8.3 Defining New Authorization Grant Types

- **rfc6749-8.3-a** MUST: an extension grant's additional token endpoint parameters are registered in the OAuth Parameters registry.

## 8.5 Defining Additional Error Codes

- **rfc6749-8.5-a** MUST: an error code used with a registered token type, parameter or extension grant is registered.
- **rfc6749-8.5-b** MUST: an error code the server answers follows the error ABNF.
- **rfc6749-8.5-c** SHOULD: an extension's error code is prefixed by a name that identifies it.

## 10.1 Client Authentication

- **rfc6749-10.1-a** MUST NOT: the server issues a password or other credentials for client authentication to a browser-based client, or to a native app but for one installation of it on one device.
- **rfc6749-10.1-b** SHOULD: where a client cannot be authenticated, its identity is checked otherwise, such as by its registered redirection URIs.

## 10.2 Client Impersonation

- **rfc6749-10.2-a** MUST: the server authenticates the client wherever it can.
- **rfc6749-10.2-b** SHOULD: where a client cannot be authenticated, other means protect resource owners from a client posing as it.
- **rfc6749-10.2-c** SHOULD: the resource owner authenticates explicitly and is told the client, the scope asked and its lifetime.
- **rfc6749-10.2-d** SHOULD NOT: a repeated authorization request from a client that is not authenticated is granted without the resource owner taking part.

## 10.3 Access Tokens

- **rfc6749-10.3-a** MUST: access tokens are kept confidential in storage, shared only by the server, the resource servers they are for, and the client.
- **rfc6749-10.3-b** MUST: no one but the server can make, change or guess a valid access token.
- **rfc6749-10.3-c** SHOULD: the client's identity is taken into account in deciding the scope to issue.

## 10.4 Refresh Tokens

- **rfc6749-10.4-a** MUST: refresh tokens are kept confidential in storage, shared only by the server and the client.
- **rfc6749-10.4-b** MUST: the server keeps each refresh token bound to the client it was issued to.
- **rfc6749-10.4-c** MUST: where the client is authenticated, a refresh token's binding to it is checked.
- **rfc6749-10.4-d** SHOULD: where the client is not authenticated, other means detect a refresh token's abuse.
- **rfc6749-10.4-e** MUST: no one but the server can make, change or guess a valid refresh token.

## 10.7 Resource Owner Password Credentials

- **rfc6749-10.7-a** SHOULD: the resource owner password credentials grant is used as little as can be.
  out-of-scope: the resource owner password credentials grant is not offered.

## 10.10 Credentials-Guessing Attacks

- **rfc6749-10.10-a** MUST: access tokens, codes, refresh tokens, passwords and client credentials cannot be guessed.
- **rfc6749-10.10-b** MUST: the chance of guessing a token or other credential the server makes, not one meant for an end user to handle, is at most 2^-128.
- **rfc6749-10.10-c** SHOULD: the chance of guessing a token or other credential the server makes, not one meant for an end user to handle, is at most 2^-160.
- **rfc6749-10.10-d** MUST: credentials meant for end users are protected against guessing by other means.

## 10.12 Cross-Site Request Forgery

- **rfc6749-10.12-a** MUST: the authorization endpoint is protected against cross-site request forgery, and no client obtains an authorization without the resource owner's knowing consent.

## 10.14 Code Injection and Input Validation

- **rfc6749-10.14-a** MUST: every value received, `state` and `redirect_uri` among them, is validated and sanitized before it is used.

## B Use of application/x-www-form-urlencoded Media Type

- **rfc6749-B-a** MUST: form-encoded names and values the server makes are encoded as UTF-8 before they are escaped.
