# RFC 7009: OAuth 2.0 Token Revocation

## 2 Token Revocation

- **rfc7009-2-a** MUST: a refresh token can be revoked at the revocation endpoint.
- **rfc7009-2-b** SHOULD: an access token can be revoked at the revocation endpoint.
- **rfc7009-2-c** MUST: the revocation endpoint's URL is an absolute URI without a fragment, as RFC 6749 §3.1 says of endpoints.
- **rfc7009-2-d** MUST: the revocation endpoint published is an https URL, never an http one.
  note: N-https

## 2.1 Revocation Request

- **rfc7009-2.1-a** MUST: a revocation request without `token` is refused.
- **rfc7009-2.1-b** MUST: a token not found by its `token_type_hint` is looked for among every other token type the server supports.
- **rfc7009-2.1-c** SHOULD: revoking a refresh token also revokes the access tokens issued under the same grant, where access tokens can be revoked.

## 5 Security Considerations

- **rfc7009-5-a** MUST: the countermeasures against denial of service applied at the token endpoint are applied at the revocation endpoint.
- **rfc7009-5-b** MUST: a client cannot make the server do unbounded work with invalid token type hints.
