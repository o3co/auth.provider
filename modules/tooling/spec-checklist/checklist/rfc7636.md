# RFC 7636: Proof Key for Code Exchange by OAuth Public Clients

## 4.4 Server Returns the Code

- **rfc7636-4.4-a** MUST: an authorization code is issued bound to the `code_challenge` and `code_challenge_method` it was asked with.
- **rfc7636-4.4-b** MUST NOT: the server hands out the `code_challenge` in a form others can read, such as inside the code.

## 4.4.1 Error Response

- **rfc7636-4.4.1-a** MUST: an authorization request without `code_challenge`, where the server requires PKCE, is answered with the error `invalid_request`.
- **rfc7636-4.4.1-b** SHOULD: that error's description says a code challenge is required.
- **rfc7636-4.4.1-c** MUST: an authorization request asking for a transformation the server does not support is answered with the error `invalid_request`.
- **rfc7636-4.4.1-d** SHOULD: that error's description says the transformation is not supported.

## 4.5 Client Sends the Authorization Code and the Code Verifier to the Token Endpoint

- **rfc7636-4.5-a** MUST: the token endpoint checks `code_verifier` with the `code_challenge_method` bound to the code.

## 4.6 Server Verifies code_verifier before Returning the Tokens

- **rfc7636-4.6-a** MUST: a token request whose `code_verifier` matches the code's challenge goes on as RFC 6749 says.
- **rfc7636-4.6-b** MUST: a token request whose `code_verifier` does not match the code's challenge is answered with the error `invalid_grant`.

## 7.2 Protection against Eavesdroppers

- **rfc7636-7.2-a** SHOULD NOT: the server offers the `plain` transformation rather than `S256` alone.
- **rfc7636-7.2-b** MUST: a `plain` challenge carried inside a stateless code is encrypted so that only the server can read it.
  out-of-scope: the `plain` transformation is not offered (`code_challenge_methods_supported` is `S256`).
