# RFC 6750: The OAuth 2.0 Authorization Framework: Bearer Token Usage

## 2 Authenticated Requests

- **rfc6750-2-a** MUST NOT: a request the server sends to another's protected resource (`idp-github`'s user lookup, through `outbound`) carries its access token by more than one method; `outbound` puts the credential in the `Authorization` header alone and refuses a header that names it again.

## 2.1 Authorization Request Header Field

- **rfc6750-2.1-a** MUST: a protected resource takes the access token in the `Authorization` header with the `Bearer` scheme.

## 2.2 Form-Encoded Body Parameter

- **rfc6750-2.2-a** MUST: a token in a form-encoded body is taken only from a single-part `application/x-www-form-urlencoded` body of ASCII characters, of a method with defined body semantics, never `GET`.
  out-of-scope: a token in the body is never read; the `Authorization` header alone is (`sender-binding`'s admission, for every protected resource).

## 2.3 URI Query Parameter

- **rfc6750-2.3-a** SHOULD: a successful answer to a request carrying its token in the URI query carries `Cache-Control: private`.
  out-of-scope: a token in the query is never read; the `Authorization` header alone is (`sender-binding`'s admission, for every protected resource).

## 3 The WWW-Authenticate Response Header Field

- **rfc6750-3-a** MUST: a request to a protected resource without credentials, or whose access token does not admit it, is answered with a `WWW-Authenticate` header, which other answers may carry too.
- **rfc6750-3-b** MUST: a challenge this specification defines uses the `Bearer` scheme.
- **rfc6750-3-c** MUST: the `Bearer` scheme in a challenge is followed by one or more auth-params.
- **rfc6750-3-d** MUST NOT: a challenge carries `realm` more than once.
- **rfc6750-3-e** MUST NOT: a challenge carries `scope` more than once.
- **rfc6750-3-f** SHOULD: a request whose access token failed is challenged with `error` saying why.
- **rfc6750-3-g** MUST NOT: a challenge carries `error`, `error_description` or `error_uri` more than once.
- **rfc6750-3-h** MUST NOT: a challenge's `scope` holds a character outside %x21 / %x23-5B / %x5D-7E, but %x20 between values.
- **rfc6750-3-i** MUST NOT: a challenge's `error` or `error_description` holds a character outside %x20-21 / %x23-5B / %x5D-7E.
- **rfc6750-3-j** MUST: a challenge's `error_uri` is a URI reference within %x21 / %x23-5B / %x5D-7E.

## 3.1 Error Codes

- **rfc6750-3.1-a** SHOULD: a request at a protected resource that misses a required parameter, carries an unsupported parameter or value, repeats a parameter, presents its token by more than one method, or is otherwise malformed, is answered `400` with `invalid_request`.
- **rfc6750-3.1-b** SHOULD: an expired, revoked, malformed or otherwise invalid access token is answered `401` with `invalid_token`.
- **rfc6750-3.1-c** SHOULD: a request needing higher privileges than its access token gives is answered `403` with `insufficient_scope`, which may name the scope needed.
- **rfc6750-3.1-d** SHOULD NOT: a request to a protected resource that lacks any authentication information, one attempting an unsupported authentication method among them, is answered with an error code or other error information.

## 5.2 Threat Mitigation

- **rfc6750-5.2-a** MUST: an access token that is a reference to its authorization cannot be guessed.
- **rfc6750-5.2-b** MUST: an access token is integrity-protected well enough that it cannot be changed.
- **rfc6750-5.2-c** SHOULD: an access token is restricted to a scope.
- **rfc6750-5.2-d** MUST: an access token whose contents are kept from the client is encrypted.
  out-of-scope: no access token's contents are kept from the client it is issued to.
- **rfc6750-5.2-e** MUST NOT: a bearer token is kept in a cookie that can be sent in the clear.
- **rfc6750-5.2-f** MUST: an access token's lifetime is limited.
- **rfc6750-5.2-g** MUST: where the server sends a bearer token to another service, it validates that service's TLS certificate chain, revocation included, and its identity.

## 5.3 Summary of Recommendations

- **rfc6750-5.3-a** MUST: where a bearer token is kept in a cookie, cross-site request forgery is guarded against.
  out-of-scope: no bearer token is kept in a cookie; a browser holds the session's cookie, which is no bearer token.
- **rfc6750-5.3-b** SHOULD: a bearer token is short-lived, an hour or less, above all one issued to a client running in a browser or another place where information may leak.
- **rfc6750-5.3-c** SHOULD: a bearer token carries an audience restriction to its intended relying parties.
- **rfc6750-5.3-d** SHOULD NOT: the server passes a bearer token in a page URL rather than in a header or a body kept confidential.
- **rfc6750-5.3-e** MUST: the server sends a bearer token to another service only over TLS.
- **rfc6750-5.3-f** MUST: a bearer token the server holds for another service goes to no party but the one it is for.
