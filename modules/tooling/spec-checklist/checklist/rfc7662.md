# RFC 7662: OAuth 2.0 Token Introspection

## 2 Introspection Endpoint

- **rfc7662-2-a** MUST: the introspection endpoint published is an https URL, so it is reached only over TLS.

## 2.1 Introspection Request

- **rfc7662-2.1-a** MUST: an introspection request without `token` is refused.
- **rfc7662-2.1-b** MUST: a token not found by its `token_type_hint` is looked for among every other token type the endpoint supports.
- **rfc7662-2.1-c** SHOULD: a token whose state cannot be told without information the request lacks is answered as not active.
- **rfc7662-2.1-d** MUST: an introspection request that carries no authorization, such as client authentication, is refused.

## 2.2 Introspection Response

- **rfc7662-2.2-a** MUST: every introspection answer is a JSON object holding a boolean `active`.
- **rfc7662-2.2-b** MUST: an authorized request for a token that is inactive, unknown, or not one the caller may introspect is answered with `active` set to `false`, never with an error.
- **rfc7662-2.2-c** SHOULD NOT: an answer for an inactive token carries any member besides `active`, such as the reason it is inactive.

## 4 Security Considerations

- **rfc7662-4-a** MUST: a token is answered as active only after every check that applies to its state has passed.
- **rfc7662-4-b** MUST: a token that can expire is answered as active only before its expiry.
- **rfc7662-4-c** MUST: a token whose validity starts after its issuance is answered as active only once that start has passed.
  out-of-scope: no token is issued with a later start (`tokens`' card: a token is issued with an expiry and a lifetime, no not-before), so none is valid only later.
- **rfc7662-4-d** MUST: a token that can be revoked is answered as active only when it has not been revoked.
- **rfc7662-4-e** MUST: a signed token is answered as active only once its signature is verified.
- **rfc7662-4-f** MUST: a token usable only at certain resource servers is answered as active only to a caller it may be used at.
- **rfc7662-4-g** SHOULD: only a caller specifically allowed to introspect may call the introspection endpoint.

## 5 Privacy Considerations

- **rfc7662-5-a** MUST: an introspection answer discloses the token's user identifiers to no party it is not meant for.
